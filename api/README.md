# bthr API

ASP.NET Core 10 / Entity Framework Core / PostgreSQL API for finance, body, health, habits, and mind tracking.

## Schema contract

`../database/migrations` is the source of truth. Apply V1-V23 to a fresh PostgreSQL database before starting the API. The API does not create or migrate tables through EF. All 20 application tables are retained.

- Users have no subscription plan column. Authenticated users can access their own finance, body, and mind resources without plan restrictions.
- Bills map API `name` to SQL `bill_name`. `dueDate`, `nextDueDate`, and `paidDate` are nullable calendar dates (`YYYY-MM-DD`). `recurrenceType` and nullable `recurrenceInterval` are stored metadata, not an automatic occurrence generator. Payment state comes from `paid_date`, never an expense-description match.
- Bill listing returns all active records unless `year` and/or `month` filter the stored `due_date`. No monthly bill instances are synthesized.
- Bill updates preserve omitted fields. Explicit null clears nullable bill dates, description, payment method, recurrence type, and recurrence interval. Updates and soft-deletes set `updated_at`.
- Investments store asset/type/category, invested amount, broker, currency, purchase date, and maturity date. Current value, profit/loss, and annual yield are not in the database or API.
- SQL uniqueness, foreign-key, check, null, text-length, and numeric-range violations return validation/conflict responses rather than exposing database errors.
- Calendar-date body/mind fields map to PostgreSQL `date`. Sleep and substance timestamps represent instants; sleep duration is generated by PostgreSQL.
- Finance `user_id` ownership is checked by the API; the current SQL does not declare foreign keys for those six tables. User uniqueness checks are application-level; the SQL does not declare unique user indexes.

These contracts replace the former `plan`, `dueDay`, `isRecurrent`, bill `endDate`, `paidThisMonth`, `currentValue`, `profitLoss`, and `annualYieldPercent` fields. Clients must use the stored fields above. Migrations were not changed to retain those obsolete API concepts.

## Endpoints

Authentication: `POST /api/auth/register`, `/login`, `/logout`, `/change-password`; `GET /api/auth/me`. The old `/api/auth/bot/token` endpoint has been removed. The optional Python agent uses `X-Bot-Api-Key` plus a verified Telegram sender ID; the API resolves the current binding on every allowed request. See [agent setup](../agent/README.md).

Resource routes start at `/api/users/{userId}` and enforce ownership:

| Area | Suffixes | Operations |
| --- | --- | --- |
| Finance | `/budgets`, `/goals`, `/earnings`, `/expenses`, `/investments`, `/bills` | List, create, update, soft-delete |
| Body | `/body/weekly-routines`, `/body/workouts`, `/body/meals`, `/body/water-intake`, `/body/body-metrics`, `/body/sleep-logs` | List, create, update, soft-delete |
| Habits | `/body/habits`, `/body/habit-logs` | List, create, update, soft-delete |
| Append-only | `/body/personal-records`, `/body/substance-logs`, `/body/symptom-logs` | List, create |
| Mind | `/mind/meditation-sessions`, `/mind/journal-entries` | List, create, update, soft-delete |

`GET /api/reports/review` accepts `start_date`, `end_date`, and `domain` (`finance`, `body`, `mind`, or `all`). Combined reports require `combine=true`.

`/api/users` administration endpoints require an admin claim. No banking integration, subscription-management, password-recovery, or self-service account-deletion endpoints are implemented. Swagger is available in Development.

## Configuration and local development

Use `.env.example` with `docker-compose.yml`, or configure these keys for `dotnet run --project bthr.Api`:

- `ConnectionStrings__DefaultConnection`: PostgreSQL connection string.
- `Jwt__SecretKey`, `Jwt__Issuer`, `Jwt__Audience`, optionally `Jwt__ExpirationMinutes` (default 60).
- `Otel__ExporterEndpoint`: OTLP gRPC endpoint, required at startup.
- `Cookie__Secure`: false only for local HTTP development; true for HTTPS deployments.
- `Bot__ApiKey`: required only for bot token issuance.

The web dev server proxies `/api` to port 5026. In production, serve the web app and proxy the API on the same origin, or explicitly configure credentialed CORS for the intended frontend origin.

## Tests

Run `dotnet test api-csharp.sln`. Unit/endpoint tests use EF InMemory; the PostgreSQL integration test is explicitly skipped unless `BTHR_TEST_POSTGRES` is set.

To verify the real schema, set `BTHR_TEST_POSTGRES` to a **disposable PostgreSQL server** connection string whose role can create databases, then run:

```powershell
$env:BTHR_TEST_POSTGRES = "Host=127.0.0.1;Port=<port>;Database=postgres;Username=postgres;Password=<test-password>"
dotnet test api-csharp.sln --filter FullyQualifiedName~PostgresSchemaTests
```

The test creates a uniquely named database, applies the checked-in SQL migrations in numeric order, compares every EF column's name/type/nullability, and exercises production cookie authentication plus creation/listing of all 19 resources. It verifies generated sleep duration, bill date clearing/filtering/deletion, reports, and unrestricted access to finance resources. The database it created is dropped in `finally`; existing databases are not migrated or cleaned. This validates migration SQL, not Flyway's history/checksum handling.

## Remaining limitations

JWT refresh/revocation, authentication rate limiting, password recovery, full personal-data export, dependency-aware readiness, and browser end-to-end tests remain separate work. `/health` currently reports process liveness only. Existing API deployment configuration needs the path, telemetry, and secure-cookie fixes described in `../PROJECT_AUDIT.md`.

## Telegram agent API additions

V23 adds only nullable unique `users.telegram_user_id`; applied V2/V12 migrations remain unchanged. `/api/telegram/*` provides short-lived QR/phone-assisted linking with authenticated web approval. Browser linking mutations require `X-Bthr-Link: 1`. Agent calls use a route-restricted, non-admin service principal; `/unlink` immediately removes the binding.

`/api/agent/catalog` exposes typed resource contracts. `/api/agent/records/{resource}` provides owner-scoped bounded reads and xmin-based ETags. `/api/agent/summary/{resource}` calculates bounded numeric summaries using allowlisted entity fields. Agent PUT/DELETE requests to existing resource endpoints require `If-Match`; the API locks and compares the row inside the mutation transaction. Read, create and domain validation continue through the existing API.

Personal records, substance logs and symptom logs now support full-replacement PUT and soft DELETE, completing CRUD for all 19 resources. `/api/meal-photos/{mealId}` lists private photo filenames; PUT/GET with a UUID suffix writes/reads normalized JPEGs. Upload is restricted to the agent, reads require owner authorization, and inactive meal images are inaccessible immediately. Configure `Photos:Root` on persistent private storage; the hourly reconciler removes objects for deleted/missing meals.
